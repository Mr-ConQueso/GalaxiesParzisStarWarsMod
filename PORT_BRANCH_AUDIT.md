# Remote branch audit for the NeoForge port

This audit compares the remote heads verified against GitHub on 2026-11-25 with local NeoForge commit `6db5bcf29` and the existing `pswg-0.0.3-port.1.jar`. The fork advertises 24 heads and upstream advertises 22. Every upstream head has an identical fork counterpart. `custom-1-21-1` and `port/neoforge-1.21.1` exist only on the fork. The remote default-branch pointers both resolve to `develop` and are excluded from the head counts.

The release contract uses `develop` at `312074c01` for the current Core, Blasters, and Gadgets bundle and the active release tag `0.0.109+1.20.1` at `bc8f64c5c` for legacy gameplay. Earlier versions and later feature branches provide comparison material. This audit follows Git ancestry, authored and generated resources, active registrations, and selected source behavior into the NeoForge implementation. The existing [parity matrix](PORT_PARITY.md) records previous runtime checks. This audit added source and artifact checks.

The findings below describe the audited commit. See the [parity matrix](PORT_PARITY.md) for subsequent fixes and verification.

## Gaps in the release scope

| Finding | Evidence in the baselines and port | Acceptance check |
| --- | --- | --- |
| **Eleven legacy wearables are missing.** | `bc8f64c5c` registers the artillerytrooper and sandtrooper backpacks, incineratortrooper tank, brown and green specialist packs, and white/green/tan light and heavy packs. Its `data/trinkets/tags/items/chest/back.json` and client renderers confirm they are wearable equipment. The corresponding IDs are absent from the port registrations and JAR. The released jumptrooper jetpack is in the port already. | Verify original IDs, acquisition and appearance, coexistence with chest armor, equip/unequip with the intended slot rules, persistence, and visibility to a second client. |
| **The wall cluster light lost its survival recipe.** | The release's `pswg:tarkin/wall_cluster_light` uses four plasteel ingots around a light panel to produce four fixtures. Both inputs and the result exist in current NeoForge. The packaged JAR has the model, block and loot data but no recipe. A normalized path comparison found 157 of 158 legacy recipe IDs in the port. | Load the original shaped recipe ID in 1.21.1 schema and craft four fixtures with the original ingredients. |
| **Released segmented-crate coverage is incomplete.** | The release's `SwgBlocks.Crate` registers `segmented_crate`, `gray_segmented_crate` and `gray_panel_crate`; their visuals were programmatic. The port's `LegacyConstruction` registers the sixteen later dyed IDs, including `brown_segmented_crate` and `gray_segmented_crate`. `segmented_crate` survives as a menu and block entity ID only. `gray_panel_crate` has no block/item registration, loot, or matching named variant. | Verify the original gray panel appearance and Creative acquisition. Make a recorded decision on the brown crate's released ID and the currently used dyed ID. Check storage, placement, drops and state across restart. |
| **Legacy translations and two English subtitle keys are missing.** | The release's PSWG namespace ships 15 locale files. The port bundles only `en_us` in each of its three namespaces. Its `assets/pswg/sounds.json` references undeclared `subtitle.pswg.blaster.fire` and `subtitle.pswg.blaster.stun`. Legacy dry-fire, reload, and bypass audio currently call the `pswg_blasters` events, which ship current samples. | Merge translations against the registered IDs, retaining current terminology for shared content. Check firing and stun subtitles and compare the audio cues in the released and current Fabric builds. |
| **The legacy blaster workbench commits edits immediately.** | Released `BlasterWorkbenchScreen` stages selections with Build/Cancel, a rotatable preview and four old/new stat comparisons. The NeoForge screen shows a static preview and sends each click directly to the menu, which immediately writes the attachment component. The existing multiplayer check covers saved attachments. | Compare preview and conflict feedback and verify that cancellation leaves the weapon untouched and Build persists the intended configuration on a dedicated server. |
| **Worrt behavior diverges from the release.** | Released `WorrtEntity` has dedicated hop movement, jump state and goals to flee players and hostile mobs. NeoForge's `Worrt` uses normal pathfinding/panic and a tongue attack that targets sand skitters. | **Astromech movement and custom paint are partial.** | Released `AstromechEntity` has leg extension/retraction goals and saved paint parameters for series, preset, base, dome and paint tint. Its paint field is fixed per registered type. | Exercise sneak-use cargo, movement and leg timing. Check command-set paint parameters in the released runtime before defining the NeoForge equivalent. |

The legacy blockstate diff also reports four separate gray light on/off IDs and two old wood gate IDs. The gray lights map to the two current toggleable `gray_imperial_light_1/2` blocks, and the gates map to the current `japor_gate` and `sequoia_gate` IDs. Current `pswg_gadgets` owns the thermal detonator. `chasuka` has a block and a seed-based acquisition path in the port, so its absent legacy item model is not a missing crop. `lightsaber_rig_test` was explicitly development-only. Model and blockstate inventories cannot detect active registrations with programmatic visuals, which is why the crate and equipment checks also inspect Java and tags.

## Features outside the approved release

### The later blaster overhaul

`feature/blasters` at `8cfa67f95` keeps one data-driven blaster item. It splits the pinned E-11D-style definition into weapon definitions, external attachments, six stance profiles and 22 shot behavior profiles. Some weapons also define inline attachments. The 34 definition files include the test weapon and alternate form definitions such as `a180_sniper` and `ca87_lethal`. The count is of files, so it includes those forms as well as distinct weapons. The lineup adds definitions for the A180, A280-CFE, Blurrg-1120, DC-17/DC-17m, DLT-19D/X, E-10/E-10R, E-22, Relby V-10 and TL-50, among others. G3D meshes and socket rigs exist for a subset of the lineup.

| System | What the branch actually adds |
| --- | --- |
| Handling | Tracks draw, wield and deploy state. Stance profiles cover pistol, rifle, heavy, ion, sniper and slugthrower handling. Stats distinguish hip and aimed spread and recoil. Recoil can have stepped pitch and a repeating yaw pattern, with a configured recovery period. |
| Ammo | Registers a 100-unit small pack and a 500-unit standard pack using `pswg:stored_charge`. Feed rules support per-shot consumption, magazines and charge stores. Ammo rules can consume item counts or component charge. The E-22 definition feeds a 60-round magazine from power packs and charges three units per round. |
| Loadouts | Stack components store attachments and the preferred mode. Attachments can change stats, mode options, and handling when folded or deployed. Timed or conditional field conversions can resolve the A180 to its sniper form and the CA-87 to a lethal form with the gas conversion attachment. |
| Shot behavior | Profiles choose server raycasts, traveling bolts or pulses. Triggers cover semi, automatic, burst and charge. Profiles can select one socket, alternate sockets or fire through all sockets, and configure scatter, falloff, impact effects and detonation. Examples include E-22 dual emission, CA-87 ion cones and repulsor effects, slug scatter, micro-grenades, and the TL-50’s held-charge concussion round. |
| Status and world effects | Explicit phases for firing, block and entity impacts, and detonation drive status, knockback, explosions and changes to fragile blocks. The branch adds ion-susceptible and fragile-block tags, a damage type and server/client definition sync. |

Taking this branch on would involve its reload schema, components, ammo economy, player actions, GUI, effects and model stack. Those changes extend the weapon system as a whole.

Historical resource names can overstate the catalog. For example, Lothcat art and Arcona art appear in branch history without corresponding active mob or species registrations at those inspected tips. A stored model or texture does not establish a playable entity, and the list above distinguishes branch registrations from asset experiments.
